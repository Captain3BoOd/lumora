# mulorder

`core/mulorder/mulorder.h` and `mulorder.cpp` (`lumora::mulorder`) give the multiplicative structure of the integers modulo `m` for every `u32` modulus above 0 (`kMaxM = 2^32 - 1`): `carmichael(m, out)` is lambda(m), `mult_order(a, m, out)` is the least `e > 0` with `a^e = 1` modulo `m`, and `primitive_root(m, out)` is the least primitive root. One call is O(sqrt(m)) trial divisions plus a small number of modular powers, with O(1) automatic memory.

Evidence label: unit tests only (CI-verified). Windows was not run locally; it is CI-only. The header pin is main `22213bf` (the header sentence about the power count was amended there; this change follows that version). The maintainer answers to the gates were relayed via Instinct; the code follows those answers.

Integer only: no floating point, no libm, no 128-bit type, no compiler builtin or intrinsic, no allocation, no recursion, no global state, no array.

## Check order and writes

For all three functions: a null `out` is NullArgument (it wins even when `m = 0`); then `m == 0` is BadModulus; then, for `mult_order` only, `gcd(a mod m, m) != 1` is NotCoprime; then, for `primitive_root` only, a modulus without a primitive root is NoPrimitiveRoot. `*out` is written once, on success only: on every failure it keeps its value (the tests compare a sentinel).

Defaults taken where the header is silent (answered by the maintainer): `a` is reduced modulo `m` first; at `m > 1` a non-unit `a` (including `a = 0` and any multiple of `m`) is NotCoprime; `m = 1` gives lambda 1, order 1 and root 0; `primitive_root(2) = 1` and `primitive_root(4) = 3`.

## Method and derivation

Multiplication: `mulmod(x, y, m)` is the `u64` product of two residues below `m` reduced at once. The product is at most `(2^32 - 2)^2 < 2^64`, so it cannot wrap. `powmod` uses binary powers (right to left); every intermediate value is below `m`; it is only called with `m >= 2`.

Factoring: trial division by 2, then by odd `d = 3, 5, ..` while `d * d <= r` (`d` is a `u64` product, so there is no wrap), and the leftover `r > 1` is prime. The odd loop makes at most 32767 iterations per factoring pass (`d = 3 .. 65535`; `65537^2 > 2^32 - 1`).

lambda(m) (`shape_of`, one factoring pass over `m`): by the Chinese remainder theorem the unit group modulo `m` is the product of the unit groups of the prime powers, so lambda(m) is the lcm of lambda of the prime powers, and the exponent of a product of groups is the lcm of the exponents. For an odd prime power, `(Z/p^e)^*` is cyclic of order `p^(e-1) (p - 1)`, so lambda is that number. For `2^e`: lambda(2) = 1, lambda(4) = 2, and lambda(2^e) = `2^(e-2)` for `e >= 3` (the group is the product of a cyclic group of order 2, generated by -1, and a cyclic group of order `2^(e-2)`, generated by 5, so its exponent is `2^(e-2)`). The same pass gives phi(m) and the number of distinct odd primes. Every partial lcm divides lambda(m) and lambda(m) <= phi(m) < 2^32, so the lcm `l / gcd(l, x) * x` is computed in `u64` and fits `u32`.

mult_order: let `x = a mod m`. The order of `x` divides lambda(m) (Lagrange for the exponent). Start with `e = lambda(m)` and, for each prime `q` of lambda(m), divide `e` by `q` while `q` divides `e` and `x^(e/q) = 1`. At the end `e` is the order: dividing by `q` is allowed exactly when the order divides `e / q`, and the primes are handled one after another, so the final `e` has no prime that could still be stripped. `m = 1` gives 1 before any power.

primitive_root: a primitive root modulo `m` exists exactly for `m = 1, 2, 4, p^k, 2 p^k` (`p` an odd prime). With `twos` the exponent of 2 and `odd` the number of distinct odd primes, the rule is `odd == 0 ? twos <= 2 : (odd == 1 && twos <= 1)`. Other moduli give NoPrimitiveRoot without a scan (the unit group is not cyclic: lambda(m) < phi(m)). When a root exists the group is cyclic of order phi(m) = lambda(m), and `g` (coprime to `m`) generates it exactly when `g^(phi/q) != 1` for every prime `q` of phi. The scan tries `g = 1, 2, ..` and stops at the first generator; a cyclic group always has one below `m`, so the final `NoPrimitiveRoot` return is not reached. `m = 1` gives 0.

## Bound on the powers of mult_order (proved)

Claim: `mult_order` makes at most `Omega(lambda) + omega(lambda) <= 40` calls of `powmod`, where Omega counts prime factors with multiplicity and omega distinct ones.

Proof. For a prime `q` of lambda with exponent `v` in lambda, the loop for `q` divides `e` by `q` while the test succeeds; `e` starts with exactly `v` factors `q`, so there are at most `v` successful tests and at most one failing test (a failing test ends the loop; so does `q` no longer dividing `e`). That is at most `v + 1` calls per prime. The leftover prime of the trial division (the loop stops at `q * q > rest`) has exponent 1 in lambda, so it costs at most 2 calls (one success, then `e` no longer has the factor, or one failure). Summing over the primes of lambda gives at most `Omega + omega` calls. Now lambda(m) < 2^32 for every `m >= 1`, so `2^Omega <= lambda < 2^32` gives `Omega <= 31`; and the product of the first 10 primes is 6469693230 > 2^32 - 1, so a number below 2^32 has at most 9 distinct primes: `omega <= 9`. Hence at most `31 + 9 = 40` powers, each of at most 32 squarings and 32 multiplications. QED. (The bound is a bound, not a measurement: the measured worst counts below are far smaller.)

No bound of this kind is claimed for `primitive_root`: the least primitive root has no tight proved bound for all `u32` primes, and the search may refactor phi for each candidate. The next section gives measurements only.

## Step counts

Structural, proved:
- `carmichael`: one factoring pass, at most 32767 odd-`d` iterations, and a handful of lcm computations; no power.
- `mult_order`: one `shape_of` pass, a gcd, one trial-division pass over lambda (at most 32767 iterations of `q`), and at most 40 powers (proved above).
- `primitive_root`: one `shape_of` pass; then for each candidate `g` one gcd and a trial-division pass over phi with an early exit at the first prime whose power is 1. So the cost is (candidates) x (a pass over phi with early exit), NOT one factoring pass in total: phi is refactored for each candidate.

Measured (a MEASUREMENT with a counting copy of the real source: a text substitution adds counters to `powmod` and to the trial-division loops; nothing else changes; the copy and its driver are not part of the change; these figures are not a claim of a bound):
- ALL 3957808 odd primes below 2^26 (every one, not a sample): most power calls for one `primitive_root` is 141 (at 39244921); the largest least root, which equals the number of candidates tried, is 111 (at 45024841); most trial-division iterations in one call 7474.
- 200000 sampled primes in `[2^26, 2^32)` (the LCG of the reference, seed 12345; a SAMPLE, not exhaustive): most power calls 119 (at 3002792521); largest root 95 (also at 3002792521); most trial-division iterations 55940. A smaller 30000-prime sample gave 88 power calls and root 73, so the sample size matters and these upper figures are only what was seen.
- `p^2`, `2 p^2` and `p^3` (11588 moduli from the same sets as the tests): most power calls 53 (at 3073704481), largest root 57 (at 2217913202).
- `mult_order`: 3 * 10^6 random pairs `(a, m)`: most power calls 14; all `m <= 2^20` with `a` in `2, 3, 5, m - 1`: most power calls 19 (at 786433).

## Mutation testing

135 real source mutants of `core/mulorder/mulorder.cpp` (one text change each: the multiply and its widening and modulus, `powmod` (bit order, shifts, the squaring, the initial value), gcd and lcm (including `u32` arithmetic), the factoring loops (start, step, bound, `d * d` in `u32`, the leftover test), the lambda and phi formulas of `2^e` and of odd prime powers, the odd-prime count, every check and its position and code, the `m == 1` shortcuts, the reduction of `a`, the strip loops and their start value (lambda, `2 * lambda`, phi), the has-root rule and its variants, the candidate loop, the exponents `phi / q` and the leftover handling, the written value, a write on failure).

Final test file: `tests/mulorder/mulorder_tests.cpp`, MD5 `1aa9f7db50d0541e178add703bf6e65a` (41 cases, 155 assertions). Every mutant ran on exactly this file, the WHOLE suite (no filter and no staging), serially, one mutant at a time, in two builds: plain (`-O0`) and with `-fsanitize=address,undefined -fno-sanitize-recover=all` on the mutated source. The test object is the same plain object in both builds: it is NOT sanitizer-instrumented; only the mutated source is. The runs use Catch2 `-a` (abort after the first failure) and `--order decl` (the cases in declaration order, so a run is deterministic and the cheap cases run first). The time limit is 200 s per run.

An earlier version of this section (on the previous test file, without the 64-residue cases) reported 14 plain TIMEOUTs after a full-suite pass in Catch2's random order, and 13 after the 14 were re-run with the filter `~[big]` (one of them, `powmod` with `e` shifted by 2, died there). That count is superseded: random order lets a long case run before the case that would fail, so a wrong-value mutant could be counted as a timeout. In declaration order five of those (`powmod` with `e` shifted by 2, `primitive_root` with `root` starting false, with the factors of `m` instead of phi, with the leftover test inverted, with the leftover exponent phi) are killed by an observed assertion in the cheap cases.
